# 04 — سير عمل الذكاء والوكلاء

**Hiroote AI**

## 1. الهدف

تنظيم استخدام أدوات ووكلاء الذكاء الاصطناعي لبناء المشروع دون فوضى أو تضارب أو تغييرات كبيرة غير قابلة للمراجعة.

## 2. الوكلاء الرئيسيون

### أ. Product & Architecture Agent

يحلل المتطلبات، يحدد النطاق، يقترح القرارات المعمارية، يكتب ADRs، ويقسم العمل إلى مراحل قابلة للتنفيذ.

### ب. Design Agent

يحول المتطلبات إلى User Flows وWireframes وFigma، يبني Design System، ويوثق حالات loading/empty/error/success/responsive/accessibility.

### ج. Implementation Agent

ينفذ Laravel وReact وDatabase وAPI وIntegrations وفق الخطة والعقود المعتمدة، ولا يغير المعمارية من تلقاء نفسه.

### د. Quality Agent

يراجع الكود والاختبارات والأمن والأداء وسلامة العقود والانحدار، ويعمل مستقلًا عن Agent المنفذ قدر الإمكان.

### هـ. Operations Agent

يبني CI/CD، Docker، المراقبة، التنبيهات، النسخ الاحتياطي، Runbooks، إدارة الحوادث والتحسينات التشغيلية.

## 3. دورة أي مهمة

1. **Intake:** صياغة المشكلة والهدف والمستخدم المتأثر.
2. **Discovery:** قراءة الوثائق والكود والتصميم والعقود ذات الصلة.
3. **Plan:** تحديد الملفات، خطوات التنفيذ، المخاطر والاختبارات.
4. **Approval:** اعتماد الخطة عند التغييرات الكبيرة أو الحساسة.
5. **Design:** تصميم الشاشة أو العقد أو تدفق البيانات.
6. **Implementation:** تنفيذ صغير ومتدرج.
7. **Self Review:** مراجعة المنفذ للتغييرات.
8. **Independent Review:** Quality Agent أو مراجع بشري.
9. **Tests:** Unit, Feature, Integration, E2E حسب النطاق.
10. **Delivery:** PR واضح مع أدلة الاختبار.
11. **Deploy:** بيئة اختبار ثم إنتاج وفق بوابات الجودة.
12. **Observe:** مراقبة الأداء والأخطاء والتكلفة.
13. **Improve:** إنشاء تحسين مبني على بيانات فعلية.

## 5. قواعد استخدام Agents

- يجب قراءة الوثائق الخمس قبل أول مساهمة.
- لا يعتمد Agent على الذاكرة وحدها عند وجود كود أو عقد فعلي.
- لا يخترع متطلبات أو أسماء حقول أو Endpoints.
- يسأل فقط عندما لا يمكن حل الغموض من المصادر المتاحة.
- يقسم التغيير الكبير إلى موجات صغيرة.
- لا يحذف كودًا أو بيانات دون توضيح الأثر.
- لا يغير ملفًا خارج النطاق لمجرد تحسين شكلي.
- يسجل الافتراضات وما لم يتم التحقق منه.
- لا يدعي نجاح اختبار لم يتم تشغيله.

## 6. بروتوكول التنفيذ

**قبل الكتابة:**

- افحص بنية المشروع.
- ابحث عن نمط مشابه قائم.
- حدد العقود وقواعد الأعمال.
- اكتب خطة قصيرة.

**أثناء التنفيذ:**

- حافظ على backward compatibility إلا إذا كان الكسر معتمدًا.
- نفذ migration آمنة.
- أضف tests بالتوازي.
- استخدم feature flags للتغييرات عالية المخاطر.

**بعد التنفيذ:**

- شغل lint وstatic analysis والاختبارات.
- راجع diff كاملًا.
- تحقق من الأمن والأداء.
- حدّث الوثائق وCHANGELOG عند الحاجة.

## 7. بوابات الموافقة

**موافقة معمارية مطلوبة عند:** إنشاء Domain جديد، تغيير قاعدة بيانات جوهري، إضافة مزود خارجي، تغيير طريقة المصادقة، تغيير عقد Hi-Share، أو إدخال تقنية جديدة.

**موافقة أمنية مطلوبة عند:** بيانات شخصية، عمليات مالية، أسرار، صلاحيات، Webhooks عامة، أدوات تغير الحالة، أو Prompt يسمح بتنفيذ فعل.

## 8. إدارة Prompts

- كل Prompt له ID وVersion وحالة draft/reviewed/active/retired.
- يخضع للاختبار على مجموعة Evaluations قبل الإنتاج.
- لا تعديلات مباشرة في الإنتاج.
- يسجل المزود والنموذج والمعلمات والنتيجة والتكلفة.
- يمنع إدراج أسرار أو بيانات غير مطلوبة.

## 9. التقييم المستمر

تبنى مجموعة Golden Conversations تغطي الأسئلة الأساسية والحالات الحساسة والأخطاء والتصعيد. تشغل عند تغيير Prompt أو Model أو Knowledge Retrieval أو Tool. تقارن الدقة، السلامة، الالتزام بالمصادر، الزمن والتكلفة.

## 10. التحسين المستمر

كل تحسين يجب أن يبدأ بمشكلة قابلة للقياس، baseline، فرضية، تغيير محدود، تجربة أو إطلاق تدريجي، ثم مقارنة النتائج. يمنع تغيير النموذج أو Prompt لمجرد الانطباع.

## 11. مخرجات كل Agent

- **Product Agent:** Scope + Plan + ADR.
- **Design Agent:** Figma + states + specs.
- **Implementation Agent:** Code + migrations + tests.
- **Quality Agent:** Review report + risks + pass/fail.
- **Operations Agent:** Pipeline + dashboards + alerts + runbook.

## 12. قاعدة التوقف

يتوقف Agent ويطلب قرارًا عند تضارب المتطلبات، احتمال فقد بيانات، تغيير أمني كبير، عملية مالية غير واضحة، أو تجاوز النطاق بصورة تؤثر على الإنتاج.
