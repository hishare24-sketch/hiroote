# 05 — التشغيل والأمن والجودة

**Hiroote AI**

## 1. استراتيجية الاختبارات

- Unit Tests لقواعد الأعمال والحسابات والاختيار والتوجيه.
- Feature Tests للـ APIs والصلاحيات والتحقق والأخطاء.
- Integration Tests للمزودين وHi-Share والـ Webhooks مع mocks وعقود حقيقية في بيئة اختبار.
- Browser/E2E للتدفقات الحرجة في لوحة الإدارة.
- Contract Tests لتثبيت شكل الطلبات والاستجابات بين Hiroote AI وHi-Share.
- Regression Tests لكل عطل تم إصلاحه.
- AI Evaluations للمحادثات، الدقة، الالتزام بالمصدر، الأمان، التصعيد والتكلفة.

## 2. بوابات الجودة

**قبل الدمج:** Pint، PHPStan/Larastan، ESLint، TypeScript، Unit/Feature tests، فحص الأسرار، مراجعة migrations.

**قبل الإنتاج:** Integration/E2E، فحص أمني، migration dry run، خطة rollback، dashboards وتنبيهات، وموافقة النشر.

## 3. الأداء

تقاس قيم P50/P95/P99 لزمن الاستجابة، زمن المزود، زمن البحث المعرفي، زمن الأدوات، Queries، Cache hit rate وQueue wait time. توضع Budgets واضحة، ولا يقبل تحسين دون baseline وقياس بعد التغيير.

## 4. اختبارات الحمل

تشمل API، المحادثات المتزامنة، Queue throughput، Webhooks، قاعدة المعرفة والتقارير. تستخدم بيانات اختبار غير حساسة، وتنفذ تدريجيًا مع حدود توقف لمنع التأثير على البيئة.

## 5. المراقبة Observability

- **Logs** منظمة بصيغة JSON وتشمل `request_id`، `trace_id`، `conversation_id`، `provider`، `model`، `latency`، `status` و`error_code` دون محتوى حساس.
- **Metrics** تشمل معدل الطلبات، الأخطاء، Tokens، التكلفة، provider health، failover، queue depth، database latency، cache وwebhook retries.
- **Tracing** يغطي الطلب من الواجهة حتى المزود والأداة وHi-Share.

## 6. التنبيهات

- **Critical:** توقف الخدمة، فشل كامل للمزودين، أخطاء مصادقة واسعة، فقد اتصال بقاعدة البيانات، Queue متوقفة، خرق ميزانية خطير.
- **High:** ارتفاع P95، زيادة أخطاء الأدوات، فشل Webhooks، failover متكرر.
- **Medium/Low:** انخفاض جودة التقييم، قرب الميزانية، تأخر مراجعة المعرفة.

كل تنبيه له owner، قناة، cooldown، runbook وشرط إغلاق.

## 7. الأمن

- تطبيق OWASP Top 10.
- Authentication قوية وMFA للإدارة عند توفرها.
- RBAC بأقل صلاحية.
- تشفير الأسرار والبيانات الحساسة.
- CSRF/XSS/SQL Injection/IDOR protections.
- Rate limiting وbot protection.
- HMAC وTimestamp وNonce للاتصالات الداخلية.
- Audit Log لكل تغيير حساس.
- Dependency scanning وsecret scanning وSAST ضمن CI.

## 8. أمن الذكاء الاصطناعي

- فصل تعليمات النظام عن محتوى المستخدم والمصادر.
- مقاومة Prompt Injection وعدم اعتبار النص المسترجع تعليمات تنفيذية.
- Allowlist للأدوات والمعاملات.
- Authorization يعاد التحقق منه عند تنفيذ الأداة، ولا يعتمد على قرار النموذج.
- Confirmation للعمليات الحساسة.
- تنقية PII وتقليل البيانات المرسلة للمزود.
- منع كشف System Prompt والمفاتيح والسجلات الداخلية.
- تسجيل سبب الرفض أو التصعيد بطريقة آمنة.

## 9. الخصوصية والاحتفاظ

تصنف البيانات إلى عام، داخلي، سري، وشديد الحساسية. تحدد مدة الاحتفاظ لكل نوع. تدعم anonymization أو deletion عند الحاجة. يمنع استخدام محادثات الإنتاج للتدريب أو الاختبار دون سياسة واعتماد.

## 10. النشر

Docker images ثابتة وموقعة قدر الإمكان. البيئات: local، test، staging، production. النشر عبر CI/CD مع migrations آمنة، health check، smoke tests وrollback. تستخدم Blue/Green أو Rolling عند نضج البنية.

## 11. النسخ الاحتياطي والاستعادة

نسخ قاعدة البيانات والملفات وفق RPO/RTO معتمدين، تشفير النسخ، اختبار استعادة دوري، ونسخة خارج نفس الخادم أو المنطقة عند الحاجة. لا تعتبر النسخة الاحتياطية ناجحة قبل اختبار الاستعادة.

## 12. إدارة الحوادث

Detect ← Triage ← Contain ← Recover ← Communicate ← Review.

كل حادث رئيسي ينتج Incident Report بلا لوم، Timeline، Root Cause، أثر، إجراءات فورية، وإجراءات منع التكرار.

## 13. Runbooks أساسية

- تعطل مزود ذكاء.
- ارتفاع التكلفة.
- تراكم Queue.
- فشل Webhooks.
- بطء قاعدة البيانات.
- فشل نشر أو Migration.
- تسريب مفتاح.
- انخفاض جودة الإجابات.

## 14. إدارة الميزانية

تحدد ميزانية شهرية عامة ولكل قسم ومزود. توجد تنبيهات عند 70% و85% و100%، وحدود صلبة اختيارية، وتوقع نهاية الشهر. أي تغيير Model يقارن الجودة والتكلفة والزمن.

## 15. التحسين المستمر

مراجعة أسبوعية للأخطاء والتصعيد والـ feedback، ومراجعة شهرية للمزودين والتكلفة والمعرفة والأمن. كل تحسين يملك owner، metric، موعد مراجعة وقرار استكمال أو rollback.

## 16. معايير الإطلاق الأول

- لا ثغرات Critical أو High غير مقبولة.
- جميع التدفقات الحرجة مختبرة.
- مزود احتياطي فعال.
- Dashboards وAlerts وRunbooks جاهزة.
- Backup restore مجرب.
- Rollback موثق ومجرب في staging.
- Audit وتكلفة وTracing تعمل من أول طلب حتى آخر إجراء.
