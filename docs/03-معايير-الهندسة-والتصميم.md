# 03 — معايير الهندسة والتصميم

**Hiroote AI**

## 1. مبادئ عامة

- البساطة قبل التعقيد.
- الوضوح قبل الاختصار المخل.
- كل منطق أعمال له مكان واحد.
- كل واجهة لها حالات loading وempty وerror وsuccess.
- كل تعديل يجب أن يكون قابلًا للاختبار والقياس والرجوع.

## 2. معايير Laravel

- Controllers رفيعة: استقبال الطلب، التفويض، استدعاء Action، إعادة Response.
- Form Requests للتحقق والتفويض الأولي.
- Actions لحالات الاستخدام الواحدة.
- Services للتنسيق المركب أو التكامل الخارجي.
- DTOs للعقود بين الطبقات.
- Policies وGates للصلاحيات.
- Events للأحداث الدومينية، Jobs للمهام غير المتزامنة.
- API Resources لتوحيد المخرجات.
- لا Repository لمجرد التغليف؛ يستخدم فقط عند وجود مصدر بيانات قابل للاستبدال أو استعلامات مركبة متكررة.

## 3. هيكل مقترح

```
app/Domains/Providers
app/Domains/Conversations
app/Domains/Knowledge
app/Domains/Integrations
app/Domains/Analytics
app/Domains/Alerts
app/Domains/Administration
```

كل Domain يحتوي Actions, DTOs, Models, Policies, Jobs, Events, Services, Tests بحسب الحاجة.

## 4. معايير React وTypeScript

- TypeScript strict.
- صفحات Inertia داخل Pages، والمكونات المشتركة داخل Components.
- فصل server state عن UI state.
- عدم استخدام `any` إلا بسبب موثق ومؤقت.
- المكونات صغيرة ومسماة حسب المسؤولية.
- Forms تستخدم schema موحدًا ورسائل خطأ عربية واضحة.
- الجداول تدعم البحث والفرز والتصفية والترقيم وحفظ الفلاتر المهمة.
- كل API contract له Type أو Schema مشترك.

## 5. نظام التصميم

- RTL افتراضي كامل.
- دعم Light وDark.
- شبكة 8px ومسافات موحدة.
- حالات ألوان ثابتة: success, warning, danger, info, neutral.
- Components أساسية: Button, Input, Select, Dialog, Drawer, Tabs, Table, Badge, Alert, Card, Chart Container, Skeleton, Empty State.
- يمنع إنشاء نسخة مختلفة من مكون موجود دون مبرر.
- Figma هو مرجع الشكل، والكود هو مرجع السلوك؛ الاختلافات توثق وتراجع.

## 6. الوصول Accessibility

- تباين AA على الأقل.
- تنقل كامل بالكيبورد.
- Focus واضح.
- Labels حقيقية لكل input.
- لا يعتمد المعنى على اللون وحده.
- الرسوم لها وصف أو جدول بديل.

## 7. قواعد API

- Versioning صريح.
- أسماء موارد لا أفعال إلا في Action endpoints المبررة.
- JSON موحد.
- أخطاء بصيغة `code, message, details, request_id`.
- Pagination وFiltering وSorting موحدة.
- Idempotency للعمليات القابلة للتكرار.
- Timeouts وRetries محددة لكل تكامل.

## 8. قواعد Git

- فروع قصيرة العمر.
- Conventional Commits.
- Pull Request واحد لكل تغيير منطقي.
- يمنع الدمج المباشر إلى main.
- كل PR يشرح السبب، النطاق، المخاطر، الاختبارات، لقطات الواجهة، وخطة rollback عند الحاجة.

## 9. جودة الكود

- Laravel Pint ناجح.
- PHPStan/Larastan بلا أخطاء على المستوى المعتمد.
- ESLint وTypeScript check ناجحان.
- لا كود ميت أو TODO بلا تذكرة.
- لا أسرار أو بيانات شخصية في fixtures أو logs.
- التعليقات تشرح لماذا، وليس ماذا يفعل الكود الواضح.

## 10. الاختبارات المطلوبة لكل نوع

- **Business Rule:** Unit أو Feature.
- **Endpoint:** Feature + Authorization + Validation.
- **Integration:** Contract test + failure scenarios.
- **UI critical flow:** Browser/E2E.
- **Bug fix:** Regression test يثبت الخطأ قبل الإصلاح.

## 11. Definition of Done

لا تعتبر المهمة مكتملة قبل:

- مطابقة Acceptance Criteria.
- مراجعة UX لجميع الحالات.
- اختبارات ناجحة.
- فحص أمني مناسب.
- عدم وجود تراجع ملحوظ في الأداء.
- توثيق القرار أو العقد الجديد.
- إضافة logs/metrics عند الحاجة.
- مراجعة بشرية أو Agent مستقل عن المنفذ.

## 12. معايير قرارات الذكاء الاصطناعي

كل كود مولد آليًا يعامل كاقتراح غير موثوق حتى يمر بالاختبار والمراجعة. يمنع قبول تغييرات واسعة دون خطة وتقسيم. أي Agent يجب أن يذكر افتراضاته، الملفات المتأثرة، المخاطر، وما لم يتمكن من التحقق منه.
