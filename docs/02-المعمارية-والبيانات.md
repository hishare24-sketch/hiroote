# 02 — المعمارية والبيانات

**Hiroote AI**

## 1. القرار المعماري

يبنى المشروع كـ Independent Modular Monolith في مستودع مستقل. يحتوي Laravel وReact داخل المشروع نفسه باستخدام Inertia. يتم الفصل الداخلي إلى Domains واضحة، مع منع أي اتصال مباشر بقاعدة بيانات Hi-Share.

## 2. المكونات الرئيسية

- Admin Dashboard.
- Authentication & Authorization.
- AI Orchestrator.
- Provider & Model Management.
- Conversation Engine.
- Knowledge & Retrieval Engine.
- Hi-Share Integration Bridge.
- Usage & Cost Engine.
- Alerts & Escalation.
- Audit & Observability.

## 3. تدفق الطلب

واجهة المستخدم أو Hi-Share ترسل الطلب ← API Gateway/Middleware يتحقق من الهوية والتوقيع ← Conversation Service ينشئ السياق ← Policy Engine يحدد المسموح ← Knowledge Engine يسترجع المعرفة ← Orchestrator يختار المزود والنموذج ← Tool Layer تنفذ الأدوات عند الحاجة ← النتيجة تسجل مع Tokens والتكلفة والتتبع ← الرد يعاد للمستخدم.

## 4. AI Orchestrator

مسؤول عن اختيار المزود والنموذج، بناء Prompt، إدراج المعرفة، إدارة الأدوات، تطبيق سياسات السلامة، retries، timeout، fallback، حساب التكلفة وتسجيل Trace موحد. يمنع استدعاء مزود مباشرة من Controller أو Job خارج هذه الطبقة.

## 5. التكامل مع Hi-Share

يتم عبر REST API بإصدار `/api/v1`، وWebhooks للأحداث. يستخدم Service Token + HMAC + Timestamp + Nonce + Idempotency Key. المشروع الجديد يقرأ أقل قدر مطلوب من البيانات وينفذ فقط الأدوات المصرح بها.

Endpoints أولية:

```
GET  /api/v1/users/{id}/context
GET  /api/v1/campaigns/{id}
GET  /api/v1/ad-spaces/{id}
GET  /api/v1/participations/{id}
GET  /api/v1/vouchers/{id}
POST /api/v1/ai-actions/create-support-ticket
POST /api/v1/ai-actions/request-human-support
POST /api/v1/ai-actions/confirm-voucher
```

## 6. الموديولات والحدود

- **Projects:** المشاريع وعضويتها وأدوارها وربط كل مشروع بـ API الخاص به. هو
  الحدّ الذي تُقسَّم عليه بقية الموديولات (ADR-0003).
- **Providers:** المزودون والنماذج والمفاتيح والصحة.
- **Conversations:** المحادثات والرسائل والأحداث والأدوات.
- **Knowledge:** المعرفة والمصادر والإصدارات والفهرسة.
- **Integrations:** عملاء API والـ Webhooks والـ DTOs.
- **Analytics:** Tokens والتكلفة والأداء والجودة.
- **Alerts:** القواعد والإرسال والتصعيد.
- **Administration:** المستخدمون والأدوار والإعدادات والتدقيق.

## 7. البيانات الأساسية

كل جدول تشغيلي يحمل `project_id`؛ ما لا يحمله فهو مشترك على مستوى الشركة عمدًا.

- `projects`, `project_user`.
- `ai_providers`, `ai_models`, `ai_provider_credentials`, `ai_provider_health_checks`, `ai_failover_events`.
- `assistants`, `assistant_levels`, `assistant_settings`, `assistant_section_settings`.
- `conversations`, `conversation_messages`, `conversation_events`, `conversation_tools`, `conversation_clicks`, `conversation_escalations`.
- `knowledge_sections`, `knowledge_screens`, `knowledge_items`, `knowledge_sources`, `knowledge_files`, `knowledge_versions`, `knowledge_tags`, `knowledge_feedback`.
- `token_usage_records`, `cost_usage_records`, `usage_budgets`.
- `alert_rules`, `alert_recipients`, `alert_events`, `notification_deliveries` —
  القاعدة تصف ما يُراقَب، والحدث يسجّل مرة تجاوزٍ واحدة تبقى مفتوحة حتى يعود
  المؤشر تحت الحد، والإيصال يسجّل محاولة وصول واحدة. الحدث يحمل **لقطة** شرط
  القاعدة لحظة التفعيل، فتعديل القاعدة لاحقًا لا يعيد كتابة تاريخها.
- `integration_apps`, `integration_credentials`, `integration_requests`, `webhook_events`.
- `audit_logs`.

## 8. قواعد قاعدة البيانات

- UUID أو ULID للكيانات العابرة بين الأنظمة.
- Foreign Keys واضحة حيث تسمح طبيعة البيانات.
- Indexes للأعمدة المستخدمة في filtering وsorting وjoins.
- JSON فقط للبيانات المرنة غير الجوهرية، وليس بديلًا للعلاقات.
- Soft Deletes للكيانات الإدارية، مع أرشفة دورية للسجلات الضخمة.
- Immutable logs لأحداث التكلفة والتدقيق.
- Encryption at rest للبيانات الحساسة والمفاتيح.
- Partitioning أو archiving لاحقًا لجداول الرسائل والأحداث عند نمو الحجم.

## 9. Queues

`ai-high` للردود الحرجة، `ai-default` للطلبات العادية، `ai-low` للمعالجة غير العاجلة، `knowledge` للفهرسة، `analytics` للتجميع، `notifications` للإشعارات، `health-checks` للفحص، `webhooks` للاستقبال وإعادة المحاولة.

## 10. الكاش

Redis لتخزين الإعدادات قصيرة العمر، نتائج السياق، rate limits، distributed locks، idempotency، health state وحالة failover. لا يخزن مصدر الحقيقة النهائي في Redis.

## 11. البحث المعرفي

يبدأ ببحث نصي كامل مع Metadata filters. عند تفعيل embeddings يستخدم Vector Store قابل للاستبدال. كل نتيجة تحمل `source_id`، `version`، `score`، `section`، `screen`، `locale`، ووقت آخر مراجعة.

## 12. إدارة الأسرار

المفاتيح داخل Secret Manager أو متغيرات بيئة مشفرة. لا تظهر كاملة في الواجهة أو logs. يتم دعم rotation وإبطال المفتاح وتاريخ آخر استخدام.

## 13. التوسع

لا تفصل خدمة إلا عند وجود قياس يثبت الحاجة: ضغط مستقل، فريق مستقل، اختلاف دورة النشر أو متطلبات أمان خاصة. أول مرشح للفصل مستقبلًا هو معالجة المعرفة الثقيلة أو خدمة Orchestrator عالية الحمل.
