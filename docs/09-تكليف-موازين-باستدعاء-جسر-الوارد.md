# 09 — تكليف: اجعل موازين يستدعي جسر هاي روت

**للمساعد الذي يعمل داخل مستودع موازين** (`mawazin1`) — لا داخل هاي روت.

هاي روت جاهز تمامًا من طرفه: النقاط الثلاث مبنيّة ومختبَرة، و٢٣ شاشة من موازين
مسجَّلة بمفاتيحها. **الناقص كودٌ في موازين وحده.**

هذه الوثيقة تصف ما تبنيه بالضبط، وما لا تبنيه، ولماذا.

---

## 0. ما تحقّق منه كاتب هذه الوثيقة

| البند | المصدر |
| --- | --- |
| عقود النقاط الثلاث | **مقروءة من كود هاي روت** — `app/Domains/Integrations/Http/Api/*` |
| مفاتيح الشاشات | **مزروعة فعلًا** — `database/seeders/MawazinScreensSeeder.php` |
| بنية موازين ومسمّياته | **مقروءة من `mawazin1`** — `front/src/router`, `NAV_ITEMS`, `backend/src/modules/ai` |
| سلوك موازين وقت التشغيل | ✅ **جُرِّب حيًّا ٢٠٢٦-٠٧-٢٩** — النتائج في §7، ومصيدتان كُشفتا في §3.1 |

---

## 1. الهدف بجملة واحدة

أن يعرف مساعد موازين **أين يقف المستخدم** حين يسأل، وأن يعود إلى هاي روت بما
جرى: محادثةً سُجِّلت، أو سؤالًا لم يُجَب.

بلا الأول يجيب المساعد عامًّا. وبلا الثاني تبقى دورة الرصد في هاي روت بلا
مادة، وحقل `conversations.screen_key` فارغًا، وسؤالُ **«هل تحسّنت نسبة الحل في
شاشة المالية بعد تعديل وصفها؟»** بلا جواب.

---

## 2. قاعدة أمنية غير قابلة للتفاوض

**مفتاح هاي روت (`hrt_…`) لا يصل المتصفّح إطلاقًا.**

هو مفتاح مشروع كامل: من يحمله يقرأ سياق كل شاشة ويكتب محادثات ورصدًا باسم
موازين. ووضعُه في `VITE_*` أو في أي حزمة أمامية يعني نشره لكل مستخدم — وأي
مستخدم يفتح أدوات المطوّر يجده.

**فكل نداء إلى هاي روت يخرج من NestJS.** الواجهة تنادي موازين، وموازين ينادي
هاي روت. لا استثناء.

---

## 3. الإعداد

في **`.env` بجذر المشروع** — لا `backend/.env`:

```env
HIROOTE_BASE_URL=https://hiroote.example.com
HIROOTE_API_KEY=hrt_xxxxxxxxxxxxxxxxxxxxxxxx
HIROOTE_TIMEOUT_MS=4000
```

**غياب المفتاح يعطّل التكامل بصمت ولا يكسر شيئًا** — الشات يعمل كما اليوم.
هذا شرط قبول: بيئةُ تطويرٍ بلا هاي روت يجب أن تبقى صالحة للعمل.

### 3.1 مصيدتان كشفهما التشغيل الحيّ ٢٠٢٦-٠٧-٢٩

كُتب هذا القسم بعد نجاح الربط فعلًا، تصحيحًا لنقصٍ في الخطوات أعلاه. كلاهما
يترك الجسر **خاملًا بلا رسالة خطأ** — وهو أسوأ من إخفاقٍ ينطق.

**الأولى — `backend/.env` لا تصل الحاوية إطلاقًا.** ليست «غير كافية» كما ظُنّ
أولًا: **لا تُستعمل**. ثلاثة أدلّة في الكود، فُحصت:

1. `backend/.dockerignore` يستثني `.env` — فلا يدخل الصورة أصلًا.
2. طبقة التشغيل في `backend/Dockerfile` تنسخ `dist` وحزم npm فقط — لا ملفّ بيئة.
3. والتطبيق يقرأ `envFilePath: '.env'` نسبةً إلى `/app` داخل الحاوية، وهو غير موجود.

وخدمة `backend` **بلا `env_file`**: بيئتها من كتلة `environment:` في
`docker-compose.yml` حصرًا، وتلك تُملأ من **`.env` بجذر المشروع**
(`/srv/mazeen/app/.env`). والأسطر الثلاثة مضافة هناك سلفًا بصيغة
`${HIROOTE_*:-}` — فيكفي ملء الجذر.

ووضعُها في `backend/.env` يُنتج **العطل الصامت نفسه** الذي بُنيت هذه الفقرة
لتفاديه: الجسر خاملٌ بلا رسالة خطأ واحدة.

**الثانية — الشاشات تُبذَر قبل أول فحص.** نداءٌ على هاي روت غير مبذور يردّ
`404 screen_not_found`، وهو خطأٌ **صحيح** لا عطل: المفتاح غير معروف حقًّا. شغّل
في هاي روت `SectionsSeeder` ثمّ `MawazinScreensSeeder` قبل أي تجربة.

وللتشغيل المحلّي: خادم هاي روت على `0.0.0.0:8000` لا `127.0.0.1`، وتناديه
الحاوية على `host.docker.internal:8000`.

## 4. ما تبنيه: وحدة `hiroote` في NestJS

```
backend/src/modules/hiroote/
  hiroote.module.ts
  hiroote.service.ts       ← كل نداء إلى هاي روت يمرّ من هنا
  hiroote.controller.ts    ← ما تحتاجه الواجهة، بلا مفتاح
  dto/report-conversation.dto.ts
  dto/report-feedback.dto.ts
  hiroote.service.spec.ts
```

### 4.1 العقود كما هي في هاي روت

المصادقة في الثلاثة: `Authorization: Bearer hrt_…`
والبادئة: `{HIROOTE_BASE_URL}/api/v1`

#### `GET /api/v1/context?screen={key}`

`key` = **اسم مسار موازين** كما هو في `front/src/router` — `finance-page` ·
`invoices-page` · `tasks-page` … الشاشات الثلاث والعشرون كلها مسجَّلة.

الرد `200`:

```jsonc
{
  "project": { "slug": "mawazin", "name": "موازين" },
  "screen": {
    "key": "finance-page",
    "name": "المالية",
    "description": "هبٌّ موحّد بتبويبات: نظرة · إيرادات · …",
    "elements": ["التبويبات الثمانية", "جدول العمليات", "…"],
    "actions": ["تسجيل دخل", "تسجيل مصروف", "…"],
    "states": ["ذمة مفتوحة", "جزئية", "مسدَّدة", "متنازَع عليها"]
  },
  "section": { "name": "الأساس", "description": "…", "ai_enabled": true },
  "knowledge": [
    { "title": "…", "kind": "faq", "summary": "…", "body": "…",
      "tags": ["…"], "version": 3, "updated_at": "2026-07-29T…Z" }
  ]
}
```

- `knowledge` **المنشور وحده** (٢٥ عنصرًا كحدّ أقصى، الأحدث أولًا). المسودة لا
  تعبر: إجابةٌ بمعلومة لم يعتمدها أحد أسوأ من لا إجابة.
- `section.ai_enabled = false` يعني **أن المالك أوقف الذكاء في هذا القسم**.
  احترمه: لا تحقن سياقًا ولا تعرض المساعد هناك.
- `chat` كتلةُ **إذن الشات** كما ضبطها المالك:

```jsonc
"chat": {
  "configured": true,                     // ← افحصه أولًا
  "enabled": true,
  "kinds": ["assistant", "group"],        // assistant|direct|group|support
  "scopes": ["project", "subscriber"],    // project|subscriber|platform|support
  "assistant_participates": true,
  "attachments_allowed": false,
  "retention_days": null                  // null = بلا حدّ (لا «لا تحفظ»)
}
```

  **`configured` يُفحص قبل كل شيء.** إن كان `false` فلا حقلَ بعده إطلاقًا:

```jsonc
"chat": { "configured": false }
```

  ومعناه **أن المالك لم يضبط سياسةً بعد** — لا أنه أغلق كل شيء. فاسقط إلى
  افتراضك المحلّي ولا تقرأ الغياب قرارًا. وكان الفرعان يخرجان بالشكل نفسه
  (`enabled: false, kinds: []`)، فمشروعٌ يصل الحقل لأول مرة كان يُطفئ مساعده
  ودعمه ومحادثات أعضائه دفعةً واحدة — بلا رسالة خطأ، لأن الحمولة صحيحةٌ نحويًّا
  وتقول قرارًا لم يُتَّخذ. (رصدَه موازين — `hishare24-sketch/hiroote#8`.)

  وحين يكون `configured: true`: **اقرأها ولا تعِد تعريفها عندك** — نسختان
  للإذن تتباعدان. ونوعُ قناةٍ خارج `kinds` لا يُفتح ولو كان مبنيًّا في واجهتك.
  **والرسائل تبقى عندك** — هاي روت لا يخزّن منها شيئًا.

  **والتطبيق قرارُك.** القنوات تعمل عندك، ولا يملك هاي روت منفذًا يُغلقها به،
  فما يصلك إعلانُ إذنٍ لا أمرُ إنفاذ. وأوضاعُ تفويضك (`local` · `dual` ·
  `hiroote`) موافقةٌ لهذا لا مخالفة له.
- مفتاح غير مسجَّل → `404` بجسم `{"error":{"code":"screen_not_found",…}}`.

#### `POST /api/v1/conversations`

```jsonc
{
  "reference": "mz-conv-8f3a91",   // مفتاح التفرّد — إلزامي، ≤64 حرفًا
  "screen": "finance-page",         // اختياري، ومفتاحٌ مجهول يُرفض بـ404
  "section": "الأساس",              // اختياري — يُتجاهل إن وُجد screen
  "external_user_id": "u_123",      // اختياري
  "user_label": "محمد",             // اختياري
  "outcome": "resolved",            // إلزامي: open|resolved|ticket|human|abandoned
  "message_count": 6,               // 0..1000
  "duration_seconds": 240,          // 0..86400
  "confidence": 42,                 // 0..100
  "rating": 4.5,                    // 1..5
  "started_at": "2026-07-29T11:20:00Z"
}
```

**`reference` هو مفتاح التفرّد**: إعادة الإرسال بنفس المرجع **تُحدِّث** الصفّ
ولا تُنشئ توأمًا. الرد `201` عند الإنشاء و`200` عند التحديث. استعمل معرّف
المحادثة في موازين نفسه — وإعادةُ الإرسال عند فشل الشبكة صارت آمنة بهذا.

#### `POST /api/v1/feedback`

```jsonc
{
  "screen": "finance-page",   // إلزامي — مجهول يُرفض بـ404
  "body": "كم الحد الأدنى للسحب؟",  // إلزامي، 3..1000
  "kind": "unanswered"        // اختياري: feedback|unanswered|suggestion
}
```

المتكرّر بالنصّ نفسه على الشاشة نفسها **يزيد عدّاده** ولا يُنشئ صفًّا
(`created: false`).

⚠️ يدخل هذا بمصدر **«رصد المساعد»**، أي **ينتظر تحققًا ميدانيًا بشريًّا** قبل
أن يُبنى عليه تعديل. لا ترفع هنا كل رسالة — ارفع ما يستحق أن يقرأه إنسان.

### 4.2 الحدّ

**١٢٠ طلبًا في الدقيقة لكل مفتاح** (لا لكل عنوان شبكة). موازين خلف بوابة
واحدة، فلولا ذلك لخنق أنشطُ مستخدميه بقيّتهم.

مع ذلك: **خزّن سياق الشاشة مؤقتًا** بمفتاحه لخمس دقائق على الأقل. ٢٣ شاشة
تعني ٢٣ مدخلًا — الوصف لا يتغيّر بين رسالتين.

### 4.3 سياسة الإخفاق — الأهم في هذه الوحدة

**هاي روت ساقطًا يجب ألّا يكسر شات موازين ولا يبطّئه.**

- مهلة قصيرة (`HIROOTE_TIMEOUT_MS`، افتراضيًّا ٤ ثوانٍ) على كل نداء.
- كل إخفاق يُبتلع ويُسجَّل `logger.warn` — **ولا يُرمى إلى المستخدم**.
- `getContext` تعيد `null` عند الإخفاق، والمساعد يجيب بسياقه العام كما اليوم.
- `reportConversation` و`reportFeedback` **لا تُنتظران في مسار الرد**: أطلقهما
  بعد إرسال الرد (أو في طابور) — تأخيرُ ردّ المستخدم لأجل إحصاءٍ في نظام آخر
  مقايضةٌ خاسرة.
- لا إعادة محاولة داخل الطلب. المرجع فريد، فإعادة الإرسال لاحقًا آمنة.

## 5. أين تُستدعى — بالضبط

### 5.1 السياق: في الخادم لا في المتصفّح

مساعد موازين يبني سياقه الموثوق خادميًّا في
`backend/src/modules/ai/ai-context.service.ts` عبر `buildStaticContext()`
و`buildLiveContext(user)`. **هناك موضع الحقن.**

المطلوب:

1. أضف إلى `AssistantDto` حقلًا اختياريًّا `screen?: string` تمرّره الواجهة.
2. الواجهة تملؤه من **اسم المسار الحالي** — `useRoute().name` — لا من مساره
   ولا من عنوانه. الاسم هو ما زُرع في هاي روت مفتاحًا.
3. في بناء السياق: إن وصل `screen`، نادِ `HirooteService.getContext(screen)`
   واحقن كتلةً بعد `MAZEEN_KNOWLEDGE`:

```
### الشاشة التي يقف عليها المستخدم الآن
الاسم: المالية (finance-page)
الوصف: …
عناصرها: …
إجراءاتها: …
حالاتها: …

### معرفة معتمَدة لهذا القسم (من مركز التحكم)
- «عنوان العنصر» (نسخة 3): …
```

**ولا تدع هذه الكتلة تتجاوز المعرفة العامة**: هي **إضافة** لا بديل. ومن
يستبدل بها `MAZEEN_KNOWLEDGE` يفقد المساعدُ إرشادَ بقيّة الأقسام.

**احترم `ai_enabled = false`**: لا حقن ولا مساعد في ذلك القسم.

### 5.2 المحادثة: عند انتهائها لا عند كل رسالة

أرسل `POST /conversations` حين تُغلق المحادثة أو تخمل. صفٌّ واحد لكل محادثة،
يُحدَّث بمرجعه.

خريطة `outcome` — احسمها بما يعرفه موازين فعلًا، ولا تخمّن:

| القيمة | متى |
| --- | --- |
| `resolved` | أجاب المساعد ولم يُصعَّد |
| `human` | حُوِّل إلى دعم بشري |
| `ticket` | فُتحت تذكرة |
| `abandoned` | أُغلقت بلا إجابة ولا تحويل |
| `open` | ما زالت جارية |

**إن لم يكن لموازين اليوم مفهومٌ لأحدها، لا تخترعه.** أرسل ما تعرفه، واترك
الباقي — حقلٌ محشوّ بتخمين يصير رقمًا في لوحة يُبنى عليه قرار.

### 5.3 الرصد: حين يعجز المساعد لا حين يجيب

أرسل `POST /feedback` عند سؤالٍ لم يُجَب أو ثقةٍ منخفضة. مصدره في هاي روت
«رصد المساعد» وينتظر تحققًا بشريًّا، فلا تُغرقه.

**لا ترسل نصّ المستخدم الخام إن حمل بياناته الشخصية.** أرسل السؤال لا هويّته.

## 6. ما لا تبنيه

| لا | لماذا |
| --- | --- |
| مفتاح هاي روت في الواجهة | مفتاح مشروع كامل يُنشر لكل مستخدم |
| خريطة تحويل بين مسارات موازين ومفاتيح هاي روت | المفاتيح **هي** أسماء المسارات؛ خريطةٌ إضافية تحتاج صيانة وتنكسر صامتة |
| نداءٌ لهاي روت في مسار الرد الحرج | ردّ المستخدم لا ينتظر إحصاءً في نظام آخر |
| إرسال كل رسالة كرصد | يُغرق دورة تحقّقٍ بشرية |
| كتابةٌ إلى هاي روت خارج النقاط الثلاث | لا نقاط أخرى — ولا تُخترع |

## 7. قائمة القبول — أُغلقت كلها ٢٠٢٦-٠٧-٢٩

أغلقها مساعد موازين على خادم هاي روت حيّ (فرع `feat/hiroote-bridge`، لم يُدمج
ولم يُنشر)، والنتائج مؤكَّدة من الطرفين:

- [x] `HIROOTE_API_KEY` لا يظهر في أي حزمة أمامية (`grep -r hrt_ front/dist` → صفر).
- [x] بلا `HIROOTE_BASE_URL` يعمل الشات كما اليوم بلا خطأ ولا بطء.
- [x] هاي روت مطفأ → الشات يعمل، ويُسجَّل `warn` واحد لا يُعرض للمستخدم.
- [x] فتح المساعد من `/finance` يحقن اسم «المالية» ووصفها وإجراءاتها في السياق.
- [x] قسمٌ `ai_enabled=false` لا يُحقن فيه سياق.
- [x] إعادة إرسال المحادثة بنفس `reference` تعيد `200` لا `201` — وفُحصت قاعدة
      هاي روت: صفٌّ واحد، و`message_count` تحدَّث ٢ ← ٤ لا تضاعف.
- [x] مفتاح شاشة غير مسجَّل يُبلَع بـ`warn` ولا يُسقط النداء الأصلي.
- [x] سياق الشاشة مخزَّن مؤقتًا، فلا يُنادى هاي روت مرتين لرسالتين متتاليتين.
- [x] الرصد المكرَّر: صفٌّ واحد و`occurrences = 2`.

**وما لم يُثبَت بعد — يُقال صراحةً:** الربط مُثبَت على مستوى **الكود والشبكة
والعقد**، لا على مستوى «فُتحت `/finance` في المتصفّح ورُئي المساعد يعي الشاشة».
الحاوية الجارية مبنيّة من `main` ولا تحمل كود الفرع. وتجربةُ المتصفّح هي وحدها
ما يكشف الفرق بين «الخادم يردّ صحيحًا» و«المستخدم يرى الفرق».

## 8. تجربة يدوية قبل أي كود

اطلب من مالك هاي روت مفتاحًا (**المشاريع ← موازين ← المفاتيح ← إصدار** — يُعرض
مرة واحدة)، ثم:

```bash
curl -s -H "Authorization: Bearer $HIROOTE_API_KEY" \
  "$HIROOTE_BASE_URL/api/v1/context?screen=finance-page" | jq .
```

ردٌّ فيه `screen.name = "المالية"` يعني أن الطرف الآخر جاهز، وأن ما تبقّى
كودك أنت.
