# 01 — المنتج والنطاق

**Hiroote AI**

## 1. تعريف المشروع

Hiroote AI مركز تحكم وإدارة لكل المشاريع التابعة للشركة. كل مشروع له لوحة تحكم
مستقلة داخل Hiroote، ولكل مشروع احتياجاته وطريقة تشغيله وأدواته ومتطلباته
المختلفة. الربط مع كل مشروع عبر API فقط.

Hiroote لا يحل محل الأنظمة الأساسية لأي مشروع، بل يعمل فوقها كطبقة ذكاء وإدارة
ومراقبة وتحليل وتنفيذ أدوات مصرح بها.

**Hi-Share هو المشروع الأول**، وليس نطاق المنصة. حيثما ورد اسمه في هذه الوثيقة
فهو مثال على مشروع، والقاعدة تسري على كل مشروع (ADR-0003).

## 2. الرؤية

إنشاء نظام ذكاء اصطناعي مؤسسي قابل للإدارة والقياس، متعدد المزودين، يعتمد على المعرفة، آمن، مراقب، وقابل للتحسين المستمر، بحيث يمكن تطويره وتشغيله بدرجة كبيرة بواسطة أدوات ووكلاء الذكاء الاصطناعي دون فقدان السيطرة الهندسية.

## 3. الأهداف

- تقديم مساعد ذكي دقيق لمستخدمي كل مشروع ولفرق الإدارة والدعم.
- إدارة المزودين والنماذج والتكلفة والأداء من لوحة واحدة، مع نسبة التكلفة إلى
  مشروعها ولو كان المفتاح مشتركًا.
- بناء قاعدة معرفة مرتبطة بأقسام وشاشات وعمليات كل مشروع على حدة.
- تنفيذ إجراءات داخل كل مشروع عبر أدوات محددة ومصرح بها فيه وحده.
- مقارنة المشاريع فيما بينها: التكلفة والجودة والتصعيد.
- تسجيل المحادثات، النقرات، الأدوات، الأخطاء، التكلفة، والتصعيد.
- تحسين الإجابات والنماذج والمعرفة اعتمادًا على بيانات قابلة للقياس.
- تمكين فرق المنتج والهندسة والدعم من مراقبة النظام والتحكم فيه.

## 4. المستخدمون

- مدير النظام.
- مدير الذكاء الاصطناعي.
- مدير المعرفة.
- محلل الأداء والتكلفة.
- فريق الدعم.
- فريق الأمن والمراجعة.
- المستخدم النهائي في كل مشروع عبر واجهة المساعد.

الدور يُمنح **لكل مشروع على حدة**: الشخص قد يكون مدير ذكاء في مشروع ومحلل تكلفة
في آخر ولا يرى ثالثًا (ADR-0003 §3).

## 5. النطاق الوظيفي

- **أ. لوحة النظرة العامة:** مؤشرات المحادثات، الجودة، الزمن، التكلفة، الأخطاء، التصعيد وحالة المزودين.
- **ب. المزودون والنماذج:** المفاتيح المشفرة، الأولوية، الحدود، الاختبار، الصحة، التحويل الاحتياطي.
- **ج. المحادثات:** الرسائل، السياق، التتبع، الأدوات، النقرات، النوايا، التقييم والنتيجة.
- **د. قاعدة المعرفة:** الأقسام، الشاشات، عناصر المعرفة، المصادر، الإصدارات، الوسوم، المراجعة والتغذية الراجعة.
- **هـ. التكامل:** إعداد أقسام كل مشروع، قراءة البيانات، تنفيذ الأدوات، Webhooks، السجلات وإعادة المحاولة.
- **ك. المشاريع:** إنشاء المشروع وربطه بـ API الخاص به، عضوية الفريق والأدوار،
  تخصيص المزودين والميزانية، والتبديل بين لوحات المشاريع.
- **و. المستويات والسلوك:** مستوى المساعد، النبرة، المبادرة، الإبداع، حدود الأدوات وقواعد التصعيد.
- **ز. التكلفة والاستهلاك:** Tokens، تكلفة المزود، الميزانيات، التوقعات والتنبيهات.
- **ح. التنبيهات:** قواعد، درجات خطورة، مستلمون، قنوات وإجراءات تلقائية.
- **ط. التدقيق:** سجل غير قابل للتلاعب لكل تغيير حساس.
- **ي. الجوال:** مراقبة سريعة، إيقاف، تحويل مزود، وضع صيانة واستعراض التنبيهات.

## 6. خارج النطاق في الإصدار الأول

- استبدال نظام مستخدمي أي مشروع.
- اتصال مباشر بقاعدة بيانات أي مشروع.
- قاعدة بيانات منفصلة لكل مشروع — العزل منطقي بـ `project_id` لا فيزيائي.
- تنفيذ عمليات مالية دون تأكيد وسياسات مستقلة.
- التعلم الذاتي غير المنضبط أو تعديل Prompts مباشرة في الإنتاج دون إصدار ومراجعة.
- بناء Microservices متعددة منذ البداية.

## 7. مؤشرات النجاح

- دقة الإجابات المقبولة بعد التقييم البشري.
- نسبة حل المحادثات دون تصعيد.
- زمن الاستجابة P50 وP95.
- معدل فشل الأدوات وطلبات API.
- تكلفة المحادثة والقسم والمستخدم.
- اكتمال المعرفة وحداثتها.
- نسبة التنبيهات الصحيحة مقابل الضوضاء.
- معدل الانحدار بعد الإصدارات.
- توافر الخدمة وصحة المزودين والـ Queues.

## 8. قواعد المنتج

- المعرفة المعتمدة مقدمة على تخمين النموذج.
- كل إجابة حساسة يجب أن تعرض درجة الثقة أو تصعد عند نقص البيانات.
- لا تنفذ أداة تغير حالة دون Authorization وتأكيد حسب مستوى الخطورة.
- المستخدم يعرف متى يتحدث مع مساعد آلي ومتى تم التصعيد لبشري.
- كل تغيير في سلوك المساعد أو المعرفة له Version وناشر وتاريخ.

## 9. مراحل التنفيذ

- **المرحلة 1:** الأساس، المصادقة، الصلاحيات، التصميم، المزودون، الصحة، التدقيق.
- **المرحلة 2:** المحادثات، Orchestrator، التكلفة، التكامل الأول مع Hi-Share.
- **المرحلة 3:** قاعدة المعرفة، البحث، RAG، التقييم والتصعيد.
- **المرحلة 4:** التنبيهات، التحليلات المتقدمة، الجوال، تحسين الأداء.
- **المرحلة 5:** التحسين المستمر، تجارب النماذج، AI Evaluation، أتمتة التشغيل.

## 10. تعريف نجاح الإصدار الأول

لوحة تعمل في الإنتاج، مزودان على الأقل مع Failover، تكامل آمن مع بيئة اختبار Hi-Share، محادثة كاملة قابلة للتتبع، تسجيل تكلفة، قاعدة معرفة أولية، اختبارات آلية، Monitoring وتنبيهات وRollback موثق.
